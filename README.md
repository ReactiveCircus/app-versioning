# App Versioning

![CI](https://github.com/ReactiveCircus/app-versioning/workflows/CI/badge.svg)
[![Maven Central](https://img.shields.io/maven-central/v/io.github.reactivecircus.appversioning/app-versioning-gradle-plugin)](https://central.sonatype.com/artifact/io.github.reactivecircus.appversioning/app-versioning-gradle-plugin)
[![License](https://img.shields.io/badge/License-Apache%202.0-blue.svg)](https://opensource.org/licenses/Apache-2.0)

A Gradle Plugin for lazily generating Android app's `versionCode` & `versionName` from Git tags.

Android Gradle Plugin 4.0 and 4.1 introduced [new APIs](https://medium.com/androiddevelopers/new-apis-in-the-android-gradle-plugin-f5325742e614) to support **lazily** computing and setting the `versionCode` and `versionName` for an APK or App Bundle. This plugin builds on top of these APIs to support common Git-based app versioning use cases with full Configuration Cache and Isolated Projects support.

## Android Gradle Plugin version compatibility

The minimum version of Android Gradle Plugin required is **9.0.0**.

Version `1.6.0` of the plugin is the final version that's compatible with AGP **8.x**.

Version `1.4.0` of the plugin is the final version that's compatible with AGP **7.x** and below.

Version `0.4.0` of the plugin is the final version that's compatible with AGP **4.0** and **4.1**.

Version `0.10.0` of the plugin is the final version that's compatible with AGP **4.2**.

## Installation

The **Android App Versioning Gradle Plugin** is available from [Maven Central](https://central.sonatype.com/artifact/io.github.reactivecircus.appversioning/app-versioning-gradle-plugin). Make sure you have added `mavenCentral()` to the plugin `repositories`:

```kt
// in settings.gradle.kts
pluginManagement {
    repositories {
        mavenCentral()
    }
}
```

The plugin can now be applied to your **Android Application** module (Gradle subproject).

<details open><summary>Kotlin</summary>

```kt
plugins {
    id("com.android.application")
    id("io.github.reactivecircus.app-versioning") version "x.y.z"
}
```

</details>

<details><summary>Groovy</summary>

```groovy
plugins {
    id 'com.android.application'
    id 'io.github.reactivecircus.app-versioning' version "x.y.z"
}
```

</details>

## Usage

The plugin offers 2 Gradle tasks for each build variant:

- `generateAppVersionInfoFor<BuildVariant>` - generates the `versionCode` and `versionName` for the `BuildVariant`. This task is automatically triggered when assembling the APK or AAB (e.g. by running `assemble<BuildVariant>` or `bundle<BuildVariant>`), and the generated `versionCode` and `versionName` are injected into the final merged `AndroidManifest.xml`.
- `printAppVersionInfoFor<BuildVariant>` - prints the latest `versionCode` and `versionName` generated by the plugin to the console if available.

### Default behavior

Without any configuration, the plugin fetches the latest Git tag in the repository, parses it as a **SemVer** string (`VersionCodeSpec.SemVer`), and computes `versionCode` using [positional notation](https://en.wikipedia.org/wiki/Positional_notation):

```
versionCode = MAJOR * 10000 + MINOR * 100 + PATCH
```

For example, for a tag `1.3.1` (or `v1.3.1`), the generated `versionCode` is `1 * 10000 + 3 * 100 + 1 = 10301`.

The default `versionName` (`VersionNameSpec.TagName`) is the name of the latest Git tag.

```
> Task :app:generateAppVersionInfoForRelease
Generated app version code: 10301.
Generated app version name: "1.3.1".
```

### Custom specs

You can customize how `versionCode` and `versionName` are computed by configuring `versionCode` (`Property<VersionCodeSpec>`) and `versionName` (`Property<VersionNameSpec>`):

```kt
appVersioning {
    versionCode.set {
        // generate an Int with `this: VersionContext` (`tag`, `variant`)
    }

    versionName.set {
        // generate a String with `this: VersionContext` (`tag`, `variant`)
    }
}
```

Inside the lambda receiver (`VersionContext`):
- `tag` (`GitTag`) encapsulates `name`, `commitsSinceLatestTag`, and `commitHash`.
- `variant` (`VariantInfo`) encapsulates `buildType`, `flavorName`, `variantName`, `isDebugBuild`, and `isReleaseBuild`.

#### SemVer-based version code

By default, `VersionCodeSpec.SemVer` reserves 2 digits for each of the **MAJOR**, **MINOR**, and **PATCH** components in a SemVer tag (accepting an optional `"v"` prefix).

To allocate 3 digits per component instead (up to 999 per component), strip a custom tag prefix, or add an offset / commit count:

<details open><summary>Kotlin</summary>

```kt
appVersioning {
    versionCode.set {
        tag.toSemVer(prefix = "android-").toVersionCode(digitsPerComponent = 3) + tag.commitsSinceLatestTag
    }
}
```

</details>

<details><summary>Groovy</summary>

```groovy
appVersioning {
    versionCode {
        tag.toSemVer("android-").toVersionCode(3) + tag.commitsSinceLatestTag
    }
}
```

</details>

`tag.toSemVer(prefix = "")` parses `GitTag#name` (after stripping `prefix` if specified) into a `SemVer` object, and `SemVer#toVersionCode(digitsPerComponent = 2)` converts it to an integer using positional notation. You can also parse arbitrary strings directly via `SemVer.parse(text)` or `SemVer.parseOrNull(text)`.

#### Combining variant info and external providers

Because `versionCode` and `versionName` are standard Gradle `Property<VersionCodeSpec>` and `Property<VersionNameSpec>` instances, you can map external `Provider`s (such as `providers.environmentVariable(...)` or `providers.gradleProperty(...)`) directly into a spec so Gradle tracks them as task inputs:

<details open><summary>Kotlin</summary>

```kt
import io.github.reactivecircus.appversioning.VersionCodeSpec

val buildNumber = providers.environmentVariable("BUILD_NUMBER").map(String::toInt).orElse(0)

appVersioning {
    versionCode.set(
        buildNumber.map { buildNum ->
            VersionCodeSpec {
                val offset = if (variant.flavorName == "paid") 1 else 0
                tag.toSemVer().toVersionCode() + buildNum + offset
            }
        }
    )
    versionName.set {
        val suffix = if (variant.isDebugBuild) " (${variant.variantName})" else ""
        "${tag.name} (${tag.commitHash})$suffix"
    }
}
```

</details>

<details><summary>Groovy</summary>

```groovy
import io.github.reactivecircus.appversioning.VersionCodeSpec

def buildNumber = providers.environmentVariable("BUILD_NUMBER").map { it.toInteger() }.orElse(0)

appVersioning {
    versionCode.set(
        buildNumber.map { buildNum ->
            {
                def offset = variant.flavorName == "paid" ? 1 : 0
                tag.toSemVer().toVersionCode() + buildNum + offset
            } as VersionCodeSpec
        }
    )
    versionName {
        def suffix = variant.debugBuild ? " (${variant.variantName})" : ""
        "${tag.name} (${tag.commitHash})${suffix}"
    }
}
```

</details>

### Tag filtering

By default the plugin uses the latest tag in the current branch for `versionCode` and `versionName` generation.

To use the latest tag matching a specific glob pattern (for example `<maj>.<min>.<patch>[-<pre-release version>]+<app-identifier>` in a monorepo):

```kt
appVersioning {
    tagFilter.set("[0-9]*.[0-9]*.[0-9]*+app-b")
}
```

## More configurations

### Disabling the plugin

To disable the plugin so the `versionCode` and `versionName` defined in the `defaultConfig` block or manifest are used instead:

```kt
appVersioning {
    enabled.set(false)
}
```

### Release build only

To generate `versionCode` and `versionName` **only** for the `release` build type:

```kt
appVersioning {
    releaseBuildOnly.set(true)
}
```

With `releaseBuildOnly` set to `true`, tasks are only registered for release variants:

```
./gradlew tasks --group=versioning

Versioning tasks
----------------
generateAppVersionInfoForRelease - Generates app's versionCode and versionName based on git tags for the release variant.
printAppVersionInfoForRelease - Prints the versionCode and versionName generated by Android App Versioning plugin (if available) to the console for the release variant.
```

### Fetching tags if none exists locally

When a local checkout does not contain Git tags (e.g. cloned with `--no-tags`), you can configure the plugin to fetch tags from remote when none exist locally:

```kt
appVersioning {
    fetchTagsWhenNoneExistsLocally.set(true)
}
```

### Custom git root directory

The plugin assumes the root Gradle project is the git root directory containing `.git`. If your root Gradle project is not the git root, specify it explicitly:

```kt
appVersioning {
    gitRootDirectory.set(rootDir.resolve("../"))
}
```

### Bare git repository

If your `.git` is a symbolic link to a **bare** git repository, specify the directory of the bare git repository explicitly (overrides `gitRootDirectory`):

```kt
appVersioning {
    bareGitRepoDirectory.set(rootDir.resolve("../.repo/projects/app.git"))
}
```

## App versioning on CI

Many CI providers only fetch a single commit by default when checking out the repository. Make sure Git tags and history are fetched (e.g. with [GitHub Actions](https://github.com/actions/checkout)):

```yaml
- uses: actions/checkout@v5
  with:
    fetch-depth: 0
```

### Retrieving the generated version code and version name

Both the `versionCode` and `versionName` generated by **app-versioning** are written to the build output directory:

```
app/build/outputs/app_versioning/<buildVariant>/version_code.txt
app/build/outputs/app_versioning/<buildVariant>/version_name.txt
```

You can read the contents of these files into shell variables:

```sh
VERSION_CODE=$(cat app/build/outputs/app_versioning/<buildVariant>/version_code.txt)
VERSION_NAME=$(cat app/build/outputs/app_versioning/<buildVariant>/version_name.txt)
```
